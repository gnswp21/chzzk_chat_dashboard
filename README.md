### 요구사항

_0. 다양한 스트리머의 채팅을 실시간으로 수집할 수 있어야 함_

1. 채팅 실시간 로그 기록
   1. 기록되는 정보
      1. 채팅 내용
      2. 채팅 이름
      3. 채팅 시간
      4. 인증비인증,구독,멤버십 정보
      5. 수집 시간(내부 분석용)
      6. 방송 날짜, 방송 제목,
2. 채팅 확인을 위한 데이터 마트 및 BI 대쉬보드 제공
   1. 치지직 API를 통해 로그인한 유저는 자신의 채팅 확인 가능
      1. 스트리머별 날짜별로 자신의 채팅 확인 가능
3. 채팅에 대한 분석 제공
   1. 실시간 채팅 개수
   2. 실시간 채팅 개수 변화량 그래프
   3. 채팅 지수 (10초당 채팅 수, 시청자수)
   4. 채터(채팅 친 사람) 정보 분류
   5. (추후 구현)채팅 분위기, 상호작용정도를 나타내

# 작업계획

프로젝트 작업 계획 (9일)
Day 1: 요구사항 확정 및 환경 준비

최종 요구사항 정리 및 프로젝트 범위 재확정
EKS 클러스터 및 Kubernetes 환경 설정 (Helm/Kustomize 활용)
기본 저장소(MySQL, Kafka, Spark, 로그 파일 저장소) 컨테이너 이미지 준비
아키텍처 다이어그램 업데이트 (태블로 온라인 연동 포함)

Day 2: 데이터 수집 모듈 구현 & MySQL 데이터 저장 연동

웹소켓 API를 통해 채팅 데이터를 실시간 수집하는 모듈 개발
수집된 데이터를 Kafka 프로듀서로 전송하는 코드 구현 및 테스트
각 채팅 메시지를 행 단위로 MySQL에 저장하는 로직 구현
데이터 스키마 설계 및 테이블 생성
Kafka로 수집한 데이터와 MySQL 저장 간 데이터 흐름 검증

Day 3: 실시간 집계 (Spark 스트리밍) 구현 & 로그 파일 배치 저장 구현

Kafka 컨슈머 역할을 하는 Spark 스트리밍 작업 개발
10초 단위 집계 로직 구현 및 테스트
집계 결과를 MySQL에 기록하는지 확인
채팅 데이터를 로그 파일(JSON Lines 또는 Parquet) 형식으로 저장하는 배치 프로세스 개발
배치 작업 스케줄러(예: cronjob) 설정

Day 4: 조회 API 및 BI 데이터 마트 준비 & 태블로 온라인 연동 및 대시보드 기본 구성

실시간 조회 및 집계 데이터를 외부에서 접근할 수 있도록 REST API 구성
날짜, 스트리머, 유저별 조회 기능 구현
API와 MySQL 연동 검증
태블로 온라인 계정 설정 및 MySQL 데이터 커넥터 구성
기본 대시보드 템플릿 (실시간 10초 집계, 채팅 로그 요약 등) 설계 및 구현
태블로에서 데이터 새로고침 스케줄링 설정

Day 5: 통합 테스트 및 모니터링 도구 구성

전체 파이프라인(데이터 수집 → 저장 → 집계 → BI 대시보드) 통합 테스트
Prometheus, Grafana 등으로 기본 모니터링 및 로깅 구성
성능 테스트 및 이슈 디버깅

Day 6: 최종 QA, 문서화 및 배포 자동화

최종 QA 및 사용자 시나리오 테스트
전체 아키텍처, API, 배포, 운영 가이드 문서화
CI/CD 파이프라인을 통한 자동 배포 스크립트 정리
태블로 온라인 대시보드 최종 검토 및 최적화
